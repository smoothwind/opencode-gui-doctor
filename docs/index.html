opencode plugin · skill + CLI

GUI error diagnosis
for coding agents

Turn a reproducible GUI failure into a recorded Playwright trace, a structured digest, and forked replay probes that test hypotheses in isolation — instead of guessing from source alone. Default-safe: allowlists, filesystem sandbox, and secret redaction.

Get started Releases GitHub

Why

When a UI action errors, renders wrong, or silently fails, the stack trace alone is often not enough. You need the console output, the failed network calls, and the app state around that specific click. This plugin gives an agent a repeatable way to reproduce and interrogate GUI bugs.

Record

Scripted Playwright scenarios with tracing → console / network / error capture plus a readable digest.

Fork

Replay to any step across isolated variants (init scripts, route mocks, patches) and diff against a baseline.

Bisect

Replay steps one-by-one and find the first action that triggers the failure.

Attach

Live CDP inspection of a running Chrome / Chromium / Electron for perf traces and real-state probing.

01Install

Not published to npm — install straight from the GitHub repository.

As an opencode plugin

npm i -D github:smoothwind/opencode-gui-doctor
{ "plugin": ["./node_modules/opencode-gui-doctor/plugin/index.ts"] }

Or clone the repo and reference the checkout directly: { "plugin": ["./opencode-gui-doctor/plugin/index.ts"] }

Add it to opencode.json and restart opencode. The plugin registers the gui-diagnostics skill, so the agent knows when and how to reach for the tools. It resolves its runtime and skill relative to itself, so it works from any project.

playwright is an optional peer dependency — install it in the project you are diagnosing, or pass browser.channel: "msedge" | "chrome" to reuse a system browser and avoid downloads.

CLI

npm i -g github:smoothwind/opencode-gui-doctor
gui-doctor env
gui-doctor record --url http://localhost:1420 --channel msedge --steps steps.json

With a project-local install you can skip the global one: npx gui-doctor env

02Tools

ToolPurpose
gui_doctor_envCheck Node, Playwright resolution, and available Chrome/Edge. Run first.
gui_trace_recordRun a scripted UI scenario with Playwright tracing; capture console/network/errors + a digest. Writes trace.zip (open with npx playwright show-trace).
gui_trace_analyzeParse a trace.zip or run dir into failed actions, page errors, console errors, failed requests, slowest actions.
gui_probe_forkForked replay probe: replay a scenario to a forkAt step across isolated variants and read probes; diffs against the baseline fork.
gui_cdp_inspectAttach to a running Chrome/Chromium/Electron over CDP, collect console/exceptions/failed requests, run probes, record a DevTools perf trace.
gui_bisectReplay steps one-by-one, probe after each, and report the first step that triggers a failure (or a custom until predicate).

Iframes: add frame: ["#my-iframe", ".inner"] to any step to scope it into an iframe chain. Probes can read across same-origin frames.

03Workflow

  1. gui_doctor_env — confirm Playwright + a browser channel.
  2. gui_trace_record — reproduce the bug with steps (goto, click, fill, expectText, …) and read the digest. expect* assertions auto-wait, and each step result lists the errors observed during that step.
  3. gui_trace_analyze — drill into the produced trace.zip for full error/console/network lists.
  4. gui_probe_fork — form 2+ hypotheses as forks that share a replay prefix; compare changedProbes and failedStepDelta against baseline.
  5. gui_cdp_inspect — when the app is already running (dev server + browser with --remote-debugging-port, or Electron), attach live for perf traces and real-state probing.

Forked replay example

{
  "url": "http://127.0.0.1:5173",
  "target": "web",
  "steps": [
    { "action": "click", "selector": "#open-modal" },
    { "action": "click", "selector": "#submit" }
  ],
  "forks": [
    { "id": "baseline", "forkAt": 1, "probes": [{ "name": "state", "expression": "() => window.__STATE__" }] },
    { "id": "api-500", "forkAt": 1, "routeMocks": [{ "url": "**/api/submit", "status": 500, "body": {} }],
      "probes": [{ "name": "state", "expression": "() => window.__STATE__" }] },
    { "id": "disable-cache", "forkAt": 1, "initScripts": ["sessionStorage.clear = () => {}"],
      "probes": [{ "name": "state", "expression": "() => window.__STATE__" }] }
  ]
}

If only api-500 reproduces the failure, the root cause is the error path around the API. If disable-cache changes behavior, investigate caching. Each diff reports changedProbes (exactly what diverged), console changes, page-error / failed-step deltas, and a11y / visual pixel diffs versus the baseline.

04Advanced diagnosis

  • Flake detection (runs: N): replays N times, each with a fresh browser, reporting a per-step pass/fail matrix and the flaky steps.
  • Failure evidence (capture): screenshotOnFailure, video, and failed request/response body capture (bounded, key-aware redaction applies).
  • Parallel forks (forkConcurrency): run up to N fork variants concurrently, each with its own isolated browser and a fork-suffixed container label.
  • CDP ownership (closeOnExit): leave the attached browser running (default) or kill it via raw CDP on exit.
  • Artifact retention (retention): prunes old runs/ directories and halves audit.log past a size cap.
  • Deterministic forks (determinism): record network.har once, replay it so forks see identical upstream responses; seed fixes Math.random, clockTime freezes the page clock.
  • CDP breakpoint probes (breakpointProbes): pause at a script url/line and read locals via evaluateOnCallFrame (Chromium only, auto-resumes).
  • Source maps: stacks are best-effort mapped back to .ts/.vue.
  • Visual + a11y diff: changed-pixel ratio and an accessibility-tree line diff versus the baseline fork.

05Security policy (default-safe)

The plugin is default-deny and enforced by both the plugin (permission gating) and the harness (runtime enforcement):

  • No JavaScript injection by default. probes, initScripts, routeMocks, patchAfterLoad and evaluate steps are refused unless allowJsProbes is enabled.
  • Outbound allowlist. Navigation is limited to localhost / 127.0.0.1 / [::1] by default; anything else asks for gui.navigate. Same for CDP endpoints (gui.cdp).
  • Filesystem sandbox. initScripts paths, storageState, outputDir and Electron executables must live inside the project root (or allowedPaths).
  • Redaction. Console text, page errors, probe results and network URLs are scrubbed of secrets (Authorization/Cookie/JWT/Bearer/AWS/GitHub tokens + sensitive key names) before returning to the model.
  • Raw traces are not attached by default. The redacted diagnostics.json is attached instead.
  • Audit log. Every run, navigation and JS grant is appended to .gui-doctor/audit.log (navigation URLs are redacted there too, so tokens in query strings never land in the log in clear text).
{
  "allowedOrigins": ["http://localhost:*", "https://staging.myapp.com"],
  "cdpAllowedEndpoints": ["http://127.0.0.1:*"],
  "allowJsProbes": false,
  "allowedPaths": ["../shared-fixtures"],
  "redaction": { "allowAttachRawTrace": false, "entropyHeuristic": false },
  "timeouts": { "step": 15000, "harness": 240000 }
}

Env overrides: GUI_DOCTOR_ALLOW_JS=1, GUI_DOCTOR_ALLOWED_ORIGINS=…, GUI_DOCTOR_ALLOW_RAW_TRACE=1, GUI_DOCTOR_NODE=/path/to/node.

06CLI reference

gui-doctor env     [--project <dir>] [--json]
gui-doctor analyze <trace.zip|run-dir> [--project <dir>]
gui-doctor record  --url <url> [options]
gui-doctor fork    --url <url> --forks <file|json> [options]
gui-doctor bisect  --url <url> --steps <file|json> [options]
gui-doctor cdp     [--endpoint http://127.0.0.1:9222] [options]
gui-doctor run     <job.json> [--project <dir>]
FlagMeaning
--project <dir>Project root (sandbox root; default: cwd)
--out <dir>Output dir (must live inside --project)
--jsonPrint the full JSON result instead of a digest
--allow-jsPermit page JavaScript (probes / init scripts / evaluate)
--har <path>Replay network from a recorded HAR (fork/bisect)
--seed <n>Seed Math.random (mulberry32)
--clock <iso|ms>Freeze the page clock
--container-label <s>Label shown by the visible container
--no-containerDisable the visible container (default: on)

Run gui-doctor --help for the full flag list.

07Requirements & artifacts

  • Node.js ≥ 20
  • Playwright (optional peer dependency) — or a system Chrome/Edge channel
  • Chromium for CDP breakpoint probes and the DevTools perf trace
  • Artifacts are written under <project>/.gui-doctor/ (runs/, jobs/); traces are attached to tool results as application/zip.
